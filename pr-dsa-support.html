1. 背景与问题

GLM-5.2 是 DSA (Deepseek Sparse Attention) MoE 模型，其 KV cache 使用双缓冲区结构：

  • kv_buffer — MLA 潜在 KV，fp8，list[NL] of (size+page_size, 1, kv_cache_dim=576)
  • index_k_with_scale_buffer — DSA 索引器，uint8，list[NL] of (num_pages, page_size*132)，其中 132 = 128B fp8 key + 4B fp32 scale

LMCache 框架已有约 70% 的 DSA 基础设施（DSA 格式 spec、vLLM 检测器、KVLayerGroupsManager 异构层组、multi_layer_kv_transfer CUDA 内核），但 SGLang 集成层完全不感知 MLA/DSA：连接器硬编码 K/V 分离和 kv_size=2，不构建层组管理器，不使用逐层格式检测。

核心缺口：SGLang 连接器 (SGLangGPUConnector) 使用单格式路径 (normalize_kv_and_discover_format)，无法处理 DSA 的两种异构张量格式。MP 适配器硬编码 k_pool + v_pool 拼接，不接受融合缓冲区。

2. 架构方案

采用 方法 A：KVLayerGroupsManager — 让 SGLang 连接器遵循 vLLM V3 连接器模式，构建层组管理器，逐组传输。DSA 的两个缓冲区自然按张量形状分裂为两个 kernel group。

GLM-5.2 DSA 双缓冲区 ├─ kv_buffer (MLA latent, fp8, 576-dim) ─┐ └─ index_k_with_scale_buffer (uint8, 132-dim) ─┤ ▼ lmc_radix_cache.py: 检测 kv_buffer + index_k_with_scale_buffer → 拼接为 kv_caches = kv_buffer + index_k_with_scale_buffer (flat list[2*NL]) → 传给 LMCacheConnector / LMCacheMPConnector ▼ SGLangGPUConnector._initialize_pointers: normalize_and_discover_per_layer_formats → 按形状分裂为两组 组0: MLA latent (NL_X_NBBS_ONE_HS, fp8, kv_cache_dim=576) 组1: DSA 索引器 (NL_X_NB_BSV_BSS, uint8, 132) KVLayerGroupsManager 构建两个 kernel group ▼ metadata.get_shapes() 返回两个形状 store()/retrieve() 分配多组 memory object to_gpu/from_gpu 逐组调用 multi_layer_kv_transfer

4. 关键代码变更

4.1 DSA 索引器格式检测

SGLang 的 DSA 索引器张量是 2-D (num_pages, page_size*132)，与 vLLM 的 3-D 布局不同。检测器通过 shape[-1] % 132 == 0 识别，并 reshape 为 3-D 以匹配 spec 的 (NB, BS, HS) 布局：

# detectors/sglang.py — DSA indexer detection
if (
    list_depth == 1
    and tensor_ndim == 2
    and first_tensor.dtype == torch.uint8
    and int(first_tensor.shape[-1]) % 132 == 0
):
    bs = int(first_tensor.shape[-1]) // 132
    kv_caches = [t.view(t.shape[0], bs, 132) for t in kv_caches]
    return lmc_ops.EngineKVFormat.NL_X_NB_BSV_BSS, kv_caches

4.2 SGLangGPUConnector 逐组传输

核心改动：从单格式 multi_layer_kv_transfer_unilateral 切换为逐组 multi_layer_kv_transfer，每组使用自己的 engine_kv_format、page_buffer_size、block_size、head_size：

# gpu_connectors.py — to_gpu 逐组传输
for i, group in enumerate(klg_manager.kernel_groups):
    group_tensor = memory_obj.get_tensor(i)
    page_buffer_size = group.shape_desc.nb * group.shape_desc.bs
    lmc_ops.multi_layer_kv_transfer(
        group_tensor,
        group_pointers[i],
        slot_mapping[start - offset : end - offset],
        device,
        page_buffer_size,
        lmc_ops.TransferDirection.H2D,
        group.engine_kv_format,          # 逐组格式（关键）
        block_size=group.shape_desc.bs,
        head_size=group.shape_desc.hs,
    )

4.3 MP 适配器 engine_group_infos

DSA 有两个 kernel group（MLA latent + DSA indexer），共享同一页地址空间（engine_group_id=0）。expand_engine_block_ids 将单组 block IDs 复制为两组：

# multi_process_adapter.py — DSA 两组 engine_group_infos
if self.use_mla and num_kv_tensors > self.num_layers:
    return [
        EngineGroupInfo(0, tuple(range(self.num_layers)), self.page_size),
        EngineGroupInfo(0, tuple(range(self.num_layers, num_kv_tensors)), self.page_size),
    ]

4.4 多组 MemoryObj 贯穿存储后端

DSA 双缓冲区在 MemoryObjMetadata 中同时有 singular（shape/dtype = group 0）和 plural（shapes/dtypes = 全列表）字段。存储后端需要用 plural 形式分配，否则 get_tensor(1) 越界：

# local_disk_backend.py — load_bytes_from_disk 多组分配
if shapes is not None and dtypes is not None:
    memory_obj = self.local_cpu_backend.allocate(shapes, dtypes, fmt)
else:
    memory_obj = self.local_cpu_backend.allocate(shape, dtype, fmt)

4.5 post_init 及早初始化层组管理器

不修复此问题，store() 中的 get_shapes() 在 _initialize_pointers 之前被调用，返回单组形状，导致 from_gpu 访问第二组时 IndexError：

# cache_engine.py — post_init 中及早初始化
if self.gpu_connector is not None and "kvcaches" in kwargs:
    self.gpu_connector.initialize_kvcaches_ptr(**kwargs)
    init_ptrs = getattr(self.gpu_connector, "_initialize_pointers", None)
    if init_ptrs is not None:
        kvcaches = getattr(self.gpu_connector, "kvcaches", None)
        if kvcaches is not None:
            init_ptrs(kvcaches)

4.6 NBBS-fused 格式 block_size 容错

SGLang MLA 使用 NL_X_NBBS_ONE_HS 格式，block 轴折叠进 PBS，block_size() 抛出 ValueError。group_layers_by_identity 增加 per_layer_tokens_per_block fallback：

# kv_layer_groups.py — block_size fallback
try:
    bs = get_block_size(kv_caches, layer_format, idx)
except ValueError:
    if per_layer_tokens_per_block is not None:
        bs = per_layer_tokens_per_block[idx]
    else:
        raise

5. 顺带修复的 V3 连接器 bug

V3 连接器 (VLLMPagedMemGPUConnectorV3) 在 to_gpu/from_gpu 中使用 self.engine_kv_format（单格式）而非 group.engine_kv_format（逐组格式）。对 DSA 两组不同格式是 bug。本 PR 修正为逐组格式，同时修正了 page_buffer_size、block_size、head_size 从 group 的 shape_desc 获取。

5.1 MHA 格式分发修复

逐层格式检测为 MHA 模型返回 TWO_X_NL_X_NBBS_NH_HS（K/V 分离列表格式），但 multi_layer_kv_transfer 不处理 KV-list 格式。在 to_gpu/from_gpu 中增加 is_mla() 分发：MLA/DSA → multi_layer_kv_transfer，MHA → multi_layer_kv_transfer_unilateral。

5.2 部分块 staging buffer 修复 (W2)

from_gpu 的 MLA staging buffer 路径对所有 chunk 大小无条件使用 staging buffer。对于不完整 chunk（end - start < chunk_size），切片后的 staging buffer 导致数据损坏。修复：增加 and end - start == self.chunk_size 条件，部分 chunk 走直接传输路径。

7. 性能对比

7.1 Prefill 吞吐量

场景 新算 token 缓存命中 吞吐 (token/s) 加速比
冷启动 prefill 1216 0 34.52 1.0×
L1 命中 (GPU radix) 64 1152 7.03 —
L2 命中 (DDN 磁盘) 192 1024 469.80 13.6×

L1 命中吞吐低（7.03 token/s）是因为仅 64 token 需计算，吞吐被固定开销摊薄。L2 命中时 192 token 的计算远快于冷启动的 1216 token，且 L2 检索仅 ~9 ms。

L2 cached-token = 1024（4 full chunks × 256 chunk_size），L1 cached-token = 1152（token 粒度）。差值 128 = 末尾不完整 chunk（save_unfull_chunk: false 不存）。

7.2 L2 存储/读取性能（8 ranks 并行）

操作 数据量/rank 延迟均值 吞吐均值 吞吐范围
Store (H2D → Disk) 0.0658 GB ~6.1 ms ~10.7 GB/s 9.97–11.45
Retrieve (Disk → H2D) 0.0658 GB ~9.4 ms ~7.0 GB/s 6.65–7.41

Store 比 Retrieve 快（10.7 vs 7.0 GB/s）——store 的 offload 是 GPU→CPU DMA 直写，retrieve 需先从磁盘读取再 H2D 拷贝。Store 细分：offload_time ~5.5 ms（GPU→CPU），put_time 0.3–1.1 ms（写入磁盘）。

8. 范围与限制

范围 决策 理由
非层式路径 (MP + IP) ✅ 实现 默认路径，DSA 支持的核心
层式路径 (use_layerwise=True) ❌ 延后 需重构 store_layer/retrieve_layer，工作量超出范围
MLA 标准模型 (DeepSeek-V3) ✅ 附带支持 MLA 是 DSA 的子集（单缓冲区），改动自然覆盖
MHA 模型 ✅ 向后兼容 保留 k_pool/v_pool 参数路径
ROCm c_ops ✅ 已支持 multi_layer_kv_transfer 已处理 DSA page_buffer_offset
纯 torch fallback ❌ 不支持 DSA 是 GPU 模型，c_ops 必需
V3 连接器 self.engine_kv_format bug 📝 已修正 V3 用单格式而非逐组格式，对 DSA 是 bug；本 PR 修正为 group.engine_kv_format
