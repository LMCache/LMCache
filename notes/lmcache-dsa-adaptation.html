01 背景：GLM-5.2 DSA 双缓冲区

GLM-5.2 是 DSA (Deepseek Sparse Attention) MoE 模型，其 KV cache 使用双缓冲区结构，与传统 MHA 的 K/V 分离布局完全不同。LMCache 框架已有约 70% 的 DSA 基础设施（格式 spec、检测器、异构层组管理器、CUDA 内核），但 SGLang 集成路径完全缺失——连接器不构建 KVLayerGroupsManager，硬编码 K/V 分离和 kv_size=2。

kv_buffer
MLA 潜在 KV，fp8
(size+page_size, 1, kv_cache_dim=576)
576 = 512 (lora) + 64 (rope)
index_k_with_scale_buffer
DSA 索引器，uint8
(num_pages, page_size×132)
132 = 128B fp8 key + 4B fp32 scale

关键配置值：

参数值说明
num_hidden_layers78Transformer 层数
kv_lora_rank512MLA 潜在维度
qk_rope_head_dim64RoPE 头维度
kv_cache_dim576512 + 64
page_size64页大小
chunk_size256LMCache 分块

02 方案：KVLayerGroupsManager 模式

采用方法 A——让 SGLang 连接器遵循 vLLM V3 连接器模式，构建 KVLayerGroupsManager，逐组传输。DSA 的两个缓冲区自然按张量形状分裂为两个层组：

层组格式层数张量形状dtype
Group 0 — KV 潜在 NL_X_NBBS_ONE_HS 78 (0–77) (990592, 1, 576) uint8 (fp8 storage)
Group 1 — DSA 索引器 NL_X_NB_BSV_BSS 78 (78–155) (15478, 64, 132) uint8

数据流：

DSA 双缓冲区 → lmc_radix_cache.py 检测 kv_buffer + index_k_with_scale_buffer
             → 拼接为 kv_caches = kv_buffer + index_k_with_scale_buffer (flat list[2×NL])
             → SGLangGPUConnector._initialize_pointers:
                 normalize_and_discover_per_layer_formats → 按形状分裂为两组
                 KVLayerGroupsManager 构建两个 kernel group
             → metadata.get_shapes() 返回两个形状
             → store()/retrieve() 分配多组 memory object
             → to_gpu/from_gpu 逐组调用 multi_layer_kv_transfer

03 实现详情：七层改动

第一层：格式检测与注册

NL_X_NB_BSV_BSS_Spec.attention_backends 增加 "SGLang MLA"；SGLang 检测器增加 DSA 索引器检测——2-D 张量、uint8、shape[-1]==132，在 MLA 检测（3-D, shape[1]==1）之后，不冲突。

第二层：CreateGPUConnector 传参

SGLang 路径增加 use_mla、metadata、layout_hints 参数，使连接器能构建 KVLayerGroupsManager。

第三层：sglang_adapter.py

init_lmcache_engine 支持 MLA kv_shape (num_layer, 1, chunk_size, 1, kv_cache_dim)；LMCacheConnector.__init__ 接受 kv_caches flat list（MLA/DSA）或 k_pool/v_pool（MHA 向后兼容）。

第四层：lmc_radix_cache.py

缓冲区获取检测 kv_buffer（MLA/DSA）或 k_buffer（MHA），DSA 额外获取 index_k_with_scale_buffer，拼接为 flat list 传给连接器。

第五层：SGLangGPUConnector — 核心改动

_initialize_pointers 改用 normalize_and_discover_per_layer_formats（逐层格式检测）+ KVLayerGroupsManager；to_gpu/from_gpu 逐组 multi_layer_kv_transfer，使用 group.engine_kv_format（逐组格式）。

修正 V3 bug vLLM V3 连接器在 to_gpu/from_gpu 中使用 self.engine_kv_format（单格式），对 DSA 两组不同格式是 bug。本实现使用 group.engine_kv_format（逐组格式），是正确做法。

第六层：MP 适配器 — MLA/DSA 线协议

_wrap_sglang_kv_caches 改为接受 flat list；LMCacheMPConnector 填充 engine_group_infos 为两组（DSA）；STORE/RETRIEVE 逐组 block IDs——DSA 索引器复用 KV 的页索引。

第七层（延后）：层式路径 MLA 支持

SGLangLayerwiseGPUConnector 仍有 # TODO: support MLA。层式路径默认关闭，且需重构 store_layer/retrieve_layer，工作量超出阶段 3 范围。临时措施：MLA/DSA 模型强制使用非层式模式。

04 存储命名格式变更

参考 nixl 的做法，用 hash 前两位散列到子目录，文件名不带模型名，更简洁。命名格式在 fs_l2_adapter.py、native_connector_l2_adapter.py、csrc/storage_backends/fs/connector.cpp 三处保持同步。

维度格式
文件名 0x{kv_rank:#010x}@{object_group_id:x}@{chunk_hash_hex}[@{cache_salt}].data
路径 base_path/{chunk_hash_hex[:2]}/{filename}
线协议 key {kv_rank:08x}@{object_group_id:x}@{chunk_hash_hex}[@{cache_salt}]

DDN 上的实际文件结构：

/ddn/glm5.2.lmcache-dsa-test/ ├── 77/ │ ├── 0x08000800@0@77c59fd7aa57021a...data # rank 0 │ ├── 0x08010801@0@77c59fd7aa57021a...data # rank 1 │ └── ... # rank 2–7 └── 37/ ├── 0x08000800@0@37fddcc9fb3a04c3...data # rank 0 └── ... # rank 1–7
设计决策：model_name="" 逆解析 _filename_to_object_key 返回 model_name=""，因为文件名中不含模型名。这是安全的：ObjectKey.__post_init__ 不拒绝空 model_name；FS 适配器是无状态的，不扫描目录，逆解析仅在测试中使用。

L2 存储（Store）

发送 721 token 的 prompt，KV cache 异步写入 DDN：

  • 16 个 .data 文件出现，分布在 2 个子目录（77/ 和 37/）
