S3
==

An L2 adapter that stores KV cache objects as S3 objects using the AWS
Common Runtime (CRT).  Works with AWS S3, S3 Express One Zone, and any
S3-compatible endpoint (MinIO, Ceph RGW, etc.).

**Required fields:**

- ``s3_endpoint``: Bucket URL -- either ``"s3://<bucket>"`` or the bare host form
  (used for non-AWS endpoints).
- ``s3_region``: AWS region string (e.g. ``"us-west-2"``).

**Optional fields:**

- ``s3_num_io_threads`` (int, default ``64``): Number of CRT I/O threads.
- ``s3_prefer_http2`` (bool, default ``true``): Negotiate HTTP/2 via ALPN.
- ``s3_enable_s3express`` (bool, default ``false``): Enable S3 Express signing
  for S3 Express One Zone buckets.
- ``disable_tls`` (bool, default ``false``): Bypass TLS when pointing at a
  plain-HTTP endpoint (e.g. a local MinIO).
- ``aws_access_key_id`` / ``aws_secret_access_key`` (string): Static
  credentials; omit both to use the AWS default credential provider chain
  (environment, EC2 instance profile, etc.).
- ``max_capacity_gb`` (float, default ``0.0``): Aggregate capacity used by
  ``get_usage()``.  A value of ``0`` disables aggregate eviction
  (``usage_fraction == -1.0``).
- ``s3_breaker_initial_cooldown_s`` (float, default ``5.0``): How long the
  circuit breaker stays open after it trips, before the adapter probes the
  endpoint again.  See `Circuit breaker`_.
- ``s3_breaker_max_cooldown_s`` (float, default ``300.0``): Upper bound for the
  doubled cooldown.  Must be greater than or equal to the initial cooldown.

Circuit breaker
---------------

After three consecutive connection-class failures (refused connection, socket
error, DNS failure, or timeout) the adapter stops dialling the endpoint:
stores, lookups and loads fail locally without a network round trip.  This
keeps a KV cache miss cheap while the backend is unreachable.

The breaker re-arms itself once ``s3_breaker_initial_cooldown_s`` has elapsed,
so a transient outage does not disable L2 for the lifetime of the process.  The
next request after the cooldown probes the endpoint; if it succeeds the adapter
resumes normally, and if the endpoint is still broken the breaker re-trips with
the cooldown doubled, up to ``s3_breaker_max_cooldown_s``.  Any successful
request resets the cooldown to its initial value.

``report_status()`` exposes ``connection_failures``, ``connection_disabled``,
and ``breaker_retry_in_seconds`` -- the last being the time until the next
probe, which distinguishes an adapter that is recovering on its own from one
that is waiting out a long backoff.  Raise the cooldowns for endpoints where
failed requests are expensive; lower them where a fast return to L2 matters
more than the occasional wasted request.

**Configuration examples:**

.. code-block:: bash

    # AWS S3 with default credentials
    --l2-adapter '{"type": "s3", "s3_endpoint": "s3://my-bucket", "s3_region": "us-west-2"}'

    # Static credentials, HTTP/2 disabled
    --l2-adapter '{"type": "s3", "s3_endpoint": "s3://my-bucket", "s3_region": "us-west-2", "s3_prefer_http2": false, "aws_access_key_id": "AKIA...", "aws_secret_access_key": "..."}'

    # Local MinIO over plain HTTP
    --l2-adapter '{"type": "s3", "s3_endpoint": "minio.local:9000", "s3_region": "us-east-1", "disable_tls": true, "aws_access_key_id": "minio", "aws_secret_access_key": "minio123"}'
