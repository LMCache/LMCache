Speculative decoding
====================

.. meta::
   :description: Speculative decoding cheaply proposes several tokens ahead, often with a smaller *draft* model, and the main model then verifies them in a single pass.
   :keywords: Speculative decoding, draft model, speculative sampling

**Speculative decoding cheaply proposes several tokens ahead, often with a smaller *draft* model, and the main model then verifies them in a single pass.**

Other proposal methods exist besides a draft model; vLLM, for example, also supports EAGLE, multi-token prediction (MTP), and n-gram matching.
Speculative decoding reduces inter-token latency mainly when the server is under low to medium load, and its gains shrink as load rises.
It works separately from KV cache reuse, and the two can run together.
It is listed here because it moves the same metrics that caching does, which means a speedup in a benchmark is not always caused by caching.
LMCache does not implement speculative decoding.
