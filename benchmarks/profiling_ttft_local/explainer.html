Validation draft, not merge-ready. This PR adds opt-in policy decisions, not a new cache or transfer engine. It ports the previously measured prototype onto dev while keeping the upstream L1 factory and write-placement APIs.

StorageManager constructs one shared policy, injects it into the L1 controller and store controller, and registers its event subscription only when construction commits. Allocation, locks, transfers, deletion and error handling remain native. L2 completion callbacks maintain advisory backing knowledge, not a second residency authority.

# StorageManager: policies are created with defer_subscription=True.
# Only after controllers/adapters have initialized successfully:
for policy in eviction_policies:
    if isinstance(policy, EventSubscriber):
        self._event_bus.register_subscriber(policy)
cleanup.pop_all()

This prevents both Profiled and ProfiledValue from leaving a callback attached to an incompletely constructed owner. See transactional registration and policy factory.

2. Decision Economics

No disk copy:       gain = N * (recompute - disk fetch) - disk write
DRAM + disk copy:   value = N * (disk fetch - host fetch)
DRAM only:         value = N * (recompute - host fetch)

LocalValueConfig prices non-overlapping prefix increments from cumulative arrays. LocalValuePolicy.select_store_targets rejects known nonpositive writes and requires the full ancestor chain. get_eviction_actions retains native eligibility checks and returns actions rather than deleting buffers. Prediction uses past demand only, not workload family labels or future requests.

# The emitter uses the same tag canonicalization as native ObjectKeys:
"tags": dict(get_request_tags(key.request_configs))
# LocalValue ignores unsupported nonempty tags, salt or TP != 1.
# Missing identity fields invalidate the snapshot rather than imply success.

Without this boundary, requests from a tagged tenant could inflate an untagged key's reuse estimate. See actual event emitter, scope validation and marginal cost arithmetic.

4. Failure Boundaries And Tests

Tests cover negative gain, copy double-counting, ancestor reachability, decay and distance, stale/missing costs, model-byte binding, namespace/layout fallback, constructor subscription lifetime, eligibility, and HTTP409 for runtime topology changes. Unsupported resident identities fall back to native ordering. The current-dev port also adapts immutable ObjectKey identities without discarding tags. Native CUDA execution and measured GPU speedups belong to separately versioned evidence.

Not implemented: capacity-aware L2 opportunity pricing, pre-D2H admission, selective load-versus-recompute routing, fleet coordination or per-signal causal attribution. Formal eight-pair qualification, representative controls and complete IPC cleanup remain unqualified. The disposable experimental runner is not shipped as a reusable benchmark tool.

Current implementation checks: focused policy/HTTP suite 73 PASS, 1 CUDA SKIP; existing regressions 117 PASS; ruff and mypy PASS. New-head GPU TTFT, clean native build, full suite, Sphinx and public CI are NOT RUN/pending. Regression source includes the actual lookup emitter (tagged rejection and untagged acceptance) and actual failed StorageManager construction; all three first failed on the old candidate and passed after the fix.

StorageManager 只构造一个共享策略，注入存储和淘汰控制器；构造成功后才订阅事件，失败不留下观察者。策略记录的磁盘备份信息只来自实际完成回调，不自行分配、删除缓存或释放锁。

# 先以 defer_subscription=True 创建策略，全部控制器初始化成功后才执行：
for policy in eviction_policies:
    if isinstance(policy, EventSubscriber):
        self._event_bus.register_subscriber(policy)
cleanup.pop_all()

因此 Profiled 和 ProfiledValue 两个入口都不会在构造失败后留下回调。对应源码：订阅提交点、策略工厂。

2. 如何判断值不值得保留

首次写磁盘：预计复用次数 ×（重算耗时 - 磁盘读取耗时）- 写入代价
已有磁盘副本时保留内存：预计复用次数 ×（磁盘读取耗时 - 内存读取耗时）
没有磁盘副本时保留内存：预计复用次数 ×（重算耗时 - 内存读取耗时）

不能把一整段前缀的重算收益重复算给每一块，也不能给内存和磁盘两份副本同时算一遍避免重算的收益。代码用累计成本的差分表达不同前缀区间；后面的缓存块依赖前面的块，准入时检查完整祖先链。预测只看过去的访问，不读取负载中的 hot/scan 标签。

# 和原生 ObjectKey 使用同一个标签解析函数：
"tags": dict(get_request_tags(key.request_configs))
# LocalValue 不学习带标签、带盐或 TP 非 1 的请求。
# 身份字段缺失时，使快照失效，不默认视为兼容。

否则另一个租户的请求可能错误地提高无标签缓存的热度。对应源码：真实查询事件、身份检查、边际成本公式。

3. 为什么本次负载收益明显

          |
    +-----+-------------------+
    |                         |

    |                         |

三对独立重启的平均 TTFT 分别降低 13.77%、20.58%、18.57%；合并后由 63.25ms 降到 52.03ms，下降 17.74%。360 个请求完成，剔除每臂 12 个预热后共 288 个测量值，每种策略 144 个；含预热的 180 组对应生成 token 一致。热点请求 52.93→33.74ms，扫描请求 73.58→70.32ms；L1 命中 token 91392→156672，L2 命中 token 47360→0，完成的 L2 写入块 342→0。这些支持整体机制，不是各信号的因果拆分。

两边条件相同：RTX5060Ti 16GB、Qwen3 架构（28 层、隐藏维度 1024）、BF16、TP1/C1、关闭 APC、eager TRITON_ATTN、384MiB GPU KV、0.5GiB L1、4GiB 文件系统 L2。两个 1536-token 热点前缀交替混入一次性扫描，请求间隔均为 1.1 秒，没有人工存储延迟。i=1..8 块的固定累计示例成本为 R=12i、F1=3i、F2=7i、W=i 毫秒，不是合格的实测成本表。提示词要求输出固定句子，输出一致并不证明 KV 张量或上下文任务质量完全正确。

数据来自旧的固定版本：策略 a101de47、基础 d0a86807、采集程序 a20056de，不代表新 dev 上的 GPU 结果。此前成本校准仍有输出差异；分配和 CUDA IPC 退出告警未消除，一组基线在发起退出后有输出处理错误。进程自行退出不等于完整资源清理验证通过。更早的快节奏开发实验约 1.56% 且策略名称检查失败，没有并入本次三对实验。不能据此宣称 Dell 客户结果。固定版本的完整结果说明及逐请求数据可进一步核算。

4. 失败路径和测试目的

测试覆盖负收益拒绝、重复计价、前缀依赖、频率衰减和复用间隔、过期成本、模型文件变化、布局和命名空间不匹配、构造失败后的订阅清理、不能淘汰的对象，以及运行中更换 L2 返回明确的 HTTP409。未知对象走原生回退；新 dev 的 ObjectKey 身份和标签也要保留。

尚未实现：按 L2 容量计算机会成本、GPU 到主机拷贝前的准入、按成本选择加载或重算、集群全局调度。八对正式实验、代表性对照、完整 IPC 清理和各信号贡献仍未验证。本次没有把存在超时清理缺口的一次性实验脚本包装成可复用工具。

当前实现的检查：策略及 HTTP 测试 73 PASS、1 CUDA SKIP；原有回归 117 PASS；ruff 和 mypy PASS。新版本 GPU TTFT、干净环境原生编译、完整测试、Sphinx 和公开 CI 均未运行或待完成。回归源码通过真实查询入口验证带标签拒绝、无标签接受，并通过真实 StorageManager 入口注入构造失败；三个新增用例都先复现失败，再验证修复。
